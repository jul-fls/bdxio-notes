# Les 20 minutes Typescript les plus rentables de votre vie !

**Aurélien Loyer et Delphin Aubin · Vendredi 8 novembre 2024 · Amphi A**

## Renforcer les contrôles progressivement

Aurélien Loyer et Delphin Aubin présentent plusieurs pratiques TypeScript sur un projet de démonstration. Le fil conducteur est d’obtenir un retour utile du compilateur et de faire apparaître plus tôt les incohérences. Ils montrent aussi comment introduire des contrôles stricts dans un code qui n’est pas encore entièrement corrigé.

## Organiser une migration de strictness

L’exemple utilise un mécanisme qui repère des commentaires dans les fichiers afin de différer certaines corrections. La construction peut continuer pendant que l’équipe reprend progressivement les zones concernées. Cette approche rend le travail visible et évite de traiter toutes les erreurs du dépôt en une seule fois.

Le parcours revient ensuite sur les fichiers restants pour regarder les erreurs signalées. L’intérêt est de transformer le renforcement du typage en un chantier que l’on peut découper et vérifier.

## Faire vérifier les cas que le code doit traiter

Un switch sur plusieurs types de slides sert à montrer un cas oublié. Les intervenants introduisent un contrôle d’exhaustivité pour que le compilateur signale qu’un type possible n’a pas été pris en compte. Le retour devient particulièrement utile lorsqu’un nouveau cas est ajouté au modèle.

D’autres exemples portent sur des unions de types et sur les opérations que l’on souhaite effectuer sur leurs valeurs. Le compilateur demande de préciser ce que l’on sait avant d’accéder à un comportement propre à un cas.

## Ce que j’en garde

Choisir une incohérence que l’on veut empêcher, puis regarder comment la représenter dans les types. Les contrôles sont plus utiles lorsque leur message correspond à un comportement que l’équipe reconnaît et peut corriger.
