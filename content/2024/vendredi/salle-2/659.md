# CodeCarbon : Comment mesurer l’impact CO2 du Machine Learning?

**Amine Saboni et Inigo Imaz Chacon · Vendredi 8 novembre 2024 · Salle 2 (E1+E2)**

## Estimer les impacts d’un calcul

Amine Saboni et Inigo Imaz Chacon présentent CodeCarbon, un outil pour estimer l’énergie et les émissions associées à l’exécution de code. Ils replacent cette mesure dans les questions environnementales posées par le machine learning. Les tâches, les modèles et l’infrastructure demandent des ressources différentes. Il faut donc préciser ce que l’on compare et sur quel périmètre.

## Ce que l’on peut observer

Pour un modèle exécuté sur une infrastructure accessible, on peut suivre les ressources pendant le calcul. Pour un modèle privé appelé par une API, l’équipe n’a pas nécessairement accès à ces informations. Les intervenants distinguent alors les mesures disponibles localement et les estimations construites à partir d’autres données, comme le volume de tokens.

Le type de tâche compte aussi. Classifier du texte et traiter un document complexe ne sollicitent pas les mêmes opérations. Une moyenne unique risque de masquer ces différences. Les comparaisons ont besoin d’un contexte : matériel, durée, tâche et conditions d’exécution.

## Instrumenter une portion du programme

La démo utilise un tracker que l’on démarre avant le travail à observer puis que l’on arrête après. Les intervenants montrent son intégration autour d’un usage de modèle. Ils présentent aussi la possibilité de transmettre les résultats à une API pour les conserver et les consulter dans un tableau de bord. On peut ainsi comparer des projets ou des exécutions dans le temps.

Le périmètre choisi dans le code influence le résultat : inclure le téléchargement, le chargement du modèle ou seulement une étape de calcul ne répond pas à la même question. Le tracker fournit un repère pour examiner ces différences.

## Utiliser les résultats pour essayer autre chose

La fin évoque plusieurs pistes d’optimisation. Le lieu d’exécution et le mix électrique jouent sur l’estimation des émissions. Pendant l’entraînement, limiter la puissance demandée au GPU peut allonger une opération tout en diminuant l’énergie nécessaire, selon le contexte. L’outil sert alors à observer le compromis sur un travail comparable.

## Ce que j’en garde

Choisir une opération reproductible, définir ce que l’on inclut dans le suivi et conserver le contexte du résultat. Cela permet de vérifier l’effet d’un changement de modèle, de matériel ou de configuration.
