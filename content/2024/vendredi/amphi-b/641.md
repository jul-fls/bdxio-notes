# Angular change de logo mais pas que.

**Florian Allainmat et David Maurin · Vendredi 8 novembre 2024 · Amphi B**

## L’évolution d’Angular dans son écosystème

Florian Allainmat et David Maurin reviennent sur les changements d’Angular. Ils replacent les nouveautés dans l’histoire d’un framework qui doit évoluer avec les attentes des équipes et les autres outils du web. Les exemples montrent ce que ces changements apportent au code quotidien et comment les introduire dans une application existante.

## Faire évoluer la syntaxe progressivement

La présentation aborde les nouveaux mécanismes de contrôle dans les templates. Une schématique aide à transformer le code et peut être appliquée à une partie du projet. Les intervenants signalent des effets sur le formatage et décrivent l’intérêt d’une migration par zones pour observer ce qui change.

Le fait qu’une transformation puisse être automatisée ne dispense pas de regarder le résultat. Les tests et les vérifications de l’interface permettent de constater que les comportements attendus sont conservés pendant la mise à jour.

## Travailler avec les signals et les observables

Les signals font partie des évolutions présentées pour gérer des valeurs réactives. Les intervenants rappellent que les observables restent présents, notamment dans le routing et les formulaires réactifs. Une application utilise donc encore plusieurs mécanismes selon les données et les interactions concernées.

Les questions de fin reviennent sur le chargement de code. Un changement de route et une condition à l’intérieur d’un écran n’offrent pas exactement le même point de déclenchement. Distinguer ces cas aide à comprendre quand le navigateur récupère une partie de l’application.

## Ce que j’en garde

Choisir une zone limitée de l’application, observer le code avant et après les transformations et vérifier les interactions. La migration peut être progressive, avec une attention aux endroits où les mécanismes réactifs se rencontrent.
